In one call, choose a useful 2-to-4-shot sequence and write its visible actions. Return only the complete JSON object described in DIRECT_SCHEMA. No separate Brief or detailed Plan exists.

For each shot provide duration_ms, opening_composition, camera_motion and description. Use one camera_motion enum per shot, static_shot for a locked camera. opening_composition owns position, framing and the state at the beginning of that shot; describe a temporal skip there if needed. description owns visible transforming gestures, their results and synchronized sounds. Do not put camera motion prose, cut phrases, timestamps, shot headings, image labels or filenames in description. The application compiles them. The total duration is DURATION_MS; proposed shot durations will be aligned proportionally to it. No compulsory final hold.

final_state describes the observable state reached at the end of the final shot, not an extra shot or a frozen pose. Use N/A for absent music. dialogue_cues must contain only the supplied ledger's exact text, in source order, with stable speaker IDs and start_ms on the requested global timeline. Otherwise use [].
